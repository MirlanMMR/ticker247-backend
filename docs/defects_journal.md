# Журнал повторяющихся ошибок ленты

Заведён 08.10.2026 по просьбе владельца: «мы это чинили — и оно вернулось».
Читают и дополняют обе стороны: владелец и Claude (локально и облако).

## Протокол (обязателен)

1. **Перед правкой ленты** — найти класс в журнале. Есть — это ПОВТОР: сначала
   выяснить, почему прошлая починка не удержалась (колонка «Почему вернулось»),
   и лишь потом чинить.
2. **Замер до и после** по живой ленте всех затронутых пулов (`quality_audit.py`).
3. **Статус честный.** Три разные вещи, не смешивать:
   - `в коде` — правка влита, тесты зелёные, но лента ещё не пересобрана;
   - `проверено на ленте` — после запуска конвейера счётчик в аудите 0 (дата);
   - `проверено на телефоне` — для всего, что рисует приложение.
   Слово «исправлено» — только после двух последних.
4. **Новая находка владельца** — запись в журнал в тот же день, даже если чинить
   будем позже. Повтор — добавить дату в колонку «Были» и разобрать причину.
5. Каждая запись называет **замок**: тест или счётчик аудита, который покраснеет
   при возврате. Нет замка — запись не закрыта.

## Общие корни (читать перед любой правкой полок и текста)

- **Шагов несколько, итог не смотрит никто.** Полка проходит ≥ 7 шагов, текст — обрезка, чистка, редактор. Правка «на входе» не держится: следующий шаг переопределяет. Лечить **последним шагом перед записью** (`final_*_guard`) и ставить на него замок.
- **Правило написано шире (или уже) причины.** Починили один путь (домен) — другие остались; запретили «Y» — заодно запретили «Z».
- **Правило написано под один язык (J33).** Новый шаблон текста, регулярка или список слов — сразу тест по ru/en/es/pt/fr (`test_rules_all_languages.py`). Владелец читает только по-русски: испанский, португальский и французский проверяет код, а не глаза.
- **Лента отстаёт от кода.** После влития PR в базе старые карточки до следующего запуска конвейера. Мерить «после» можно только прогоном стража по живым данным или после запуска.
- **Приложение верит метке сервера.** Любая серверная метка (`scope`, `country`) обязана быть правильной на выходе: клиент второй рубеж держит не по всем признакам.

## Пункт пропуска (`border.py`)

Последний шаг конвейера перед записью. Каждая строка журнала с кодом Jn имеет
детектор («фоторобот»): итоговая лента прогоняется по ним, результат — в логе
(`🛂 Пункт пропуска`) и в `border_report.md`. Закрытый класс, который нашёлся
снова, — это **возврат**: в логе `::error::`. Пункт пропуска ничего не правит
(правят стражи выше), он проверяет их работу. Новый класс в журнале = новый
детектор в `border.REGISTRY` + тест в `test_border.py`.
